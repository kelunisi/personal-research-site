这些名称不建议改

AGENTS.md
Kimi Code 和其他 Agent 用它识别项目规则。
SKILL.md、.agents/skills/
属于 Skill 扫描约定；中文用于 Skill 名称即可。
README.md
虽可改名，但保留后 GitHub 能直接展示项目说明。
.git / .obsidian / .smart-env / .gitignore
应用或版本管理内部约定，不应改名。
Skill frontmatter 与 YAML 字段
name、description、type、updated 等机器字段先保持稳定；标题和正文使用中文。
改名方式：先冻结这张映射表，再一次性迁移目录、链接、Skills、脚本和 README，最后跑全库链接检查。不要边使用边零散改名。

视频中的“宪法级”是否等于 Kimi Code 全局规则？

概念上相近，但不能简单画等号。

视频中的 L0 宪法

一套治理地位

  • 约束整个工作台和所有场景。
  • 只放“不读就会白干”的最高优先级铁律。
  • 强调只有用户有权修改，修改需要版本化。
  • 细则下沉到规范、技能和其他文档。
≈不是完全等同
Kimi Code 全局 AGENTS.md

一个全局指令入口

  • 默认位置是 ~/.kimi-code/AGENTS.md。
  • 内容作为工作区指令注入提示词。
  • 可以约束所有 Kimi Code 项目工作区。
  • 本身不自动提供版本化、权限分级或“只有用户能改”的执行机制。
对我们当前架构的准确理解：全局 AGENTS.md 是“宪法入口”，智脑项目 AGENTS.md 是“智脑运行章程”，两者合起来承担部分宪法层作用。但“宪法级”来自权威性、适用范围和修改权限，不是由文件名自动获得。
不要把 SYSTEM.md 当作宪法文件：它会完整替换 Kimi Code 默认主 Agent 的系统提示词，不是普通的全局规则追加机制。
