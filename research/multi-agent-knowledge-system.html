初始共编架构：让知识和偏好一起复利

在现有 Obsidian 库中建立受控的“智脑”区域。Kimi Code、DSH / Kimi、DSH / DeepSeek 与你共同读写同一套 Markdown，而不是一个主 Agent 加若干只读助手。

01核心角色与共同底座

KIMI CODE

知识编译与维护者

阅读资料、检索、创建和修改页面、建立链接、检查一致性。

LLM WIKI

运行机制

不是另一个软件，而是入库、查询、学习和维护的方法。

OBSIDIAN

人与知识的界面

阅读、审阅、双链、图谱和人工修改。

GITHUB

私有备份

保存规则与知识，不作为日常运行时数据库。

共同写日记：每个 Agent 都能阅读、理解并修改其他 Agent 的内容。没有主从、没有上下文包、没有各自的私有知识副本。

02四类资产

raw / 外部原始资料

网页、论文、报告等来源，归档后原则上不修改，用于事实核查。

wiki / 编译知识

来源、概念、实体和综合页。新资料必须检查对旧知识的影响。

me / 个人模型

个人背景、协作偏好和任务标准分开维护。

system / 运行规则

共编规则、模板、索引、工作流和日志。

生长不等于堆积：新增、重写、合并、限定和淘汰都是生长，目标是当前理解更准确，而不是文件更多。

共同编辑约定

  • 先读后写，基于最新文件修改
  • 原地演进，不建近义页面
  • 尊重已确认规则
  • 整合而非追加堆叠
  • 事实、综合和推断分开
  • 留下简短操作日志

索引的索引负责路由，全文搜索负责定位。数百页先用分层索引与全文搜索，规模增大后再增加机器目录、BM25 或混合检索。

05运行闭环与权限

Ingest / 入库

保存外部来源，创建来源摘要，更新相关概念和综合页。

Learn / 学习

从明确要求和优秀作品中精修任务标准。

Query / 查询

按索引读取最小上下文，有复用价值的成果才沉淀。

Lint / 维护

结构检查与语义检查分开，结构合格不等于事实正确。

Backup / 备份

私有 GitHub 只作备份，手动触发，不与问答绑定。

Evolve / 进化

发现重复建页、漏索引和误推断后修订规则本身。

边界：可自动做检索、索引、格式和明确指令更新；推断出的个人偏好、重要合并删除、重大结论变化和超出受控区域的修改先确认。

个人偏好学习

03全量备份与自动执行 Skill

备份范围

  • 全部知识、规则、模板和脚本
  • 全部中文 Skills
  • 根目录已有文件
  • .obsidian/ 和 .smart-env/
  • 只有 .git/ 内部元数据除外

执行方式

备份 Skill 使用脚本的 AutoConfirm 模式，调用后实际执行，不是只向用户展示命令。直接运行脚本仍保留人工确认。

目标仓库必须私有；保留敏感文件名、超大文件、远端不一致和禁止强推等检查。

隐私边界：配置目录也可能含个人或插件配置，整个工作区只能备份到私有 GitHub。普通对话不自动上传。

2026-11-02V1.2 · 历史方案

对话级自动循环：每次对话都带着你和相关知识

把个人模型读取、知识检索和知识沉淀从手动 Skill 扩展为智脑项目内的默认协议。重点不是全部读入，而是“总览必读、详情按需、当前任务必读”。

01默认对话循环

读取个人模型总览
→
通过索引轻量检索
→
回答或创作
→
判断是否有复用价值
→
去重并写回
同一话题不重复启动：话题明显变化时针对新主题重新检索；没有相关知识就直接回答，不强行凑引用。

02个人模型总览与详情

me/_index.md

每个新对话必读。只放身份背景摘要、稳定协作偏好、任务标准清单和详情链接。

个人背景与协作详情

profile.md 与 collaboration.md 只在需要完整信息时展开。

任务标准

执行哪项工作就读取哪份任务文档，不加载所有无关任务标准。

个人模型总览必须保持精简，不能变成第二份完整档案。修改详情后同步检查总览摘要。

03轻量检索

启动时

  • 读取 AGENTS、START 和个人模型总览
  • 判断问题类型和关键词
  • 查看相关领域索引和元数据
  • 有候选结果才读取正文或段落

停止与展开

  • 现有信息足够就停止扩大检索
  • 事实核验或 Wiki 不足时才读 raw
  • 只有实际使用页面才说明来源
  • 检索不到时不假装知识库有答案

04选择性自动沉淀

值得沉淀
  • 用户明确要求记住的内容
  • 稳定的个人背景或偏好
  • 可复用的方法、决策和比较
  • 解决问题的经验与例外
  • 有来源支持的新知识
不应沉淀
  • 寒暄、重复内容和一次性细节
  • 未核实事实和 Agent 臆测
  • 密码、凭据和偶然敏感信息
  • 完整聊天记录
  • 没有新信息的日常问答

采用“卡片化提炼、页面化沉淀”：结论、适用条件、来源性质和相关链接可以保持原子化，但优先合并进已有页面，不逢结论就新建文件。

个人推断仍需确认：个人背景、协作偏好和任务规则的推断进入各自页面的待确认区；Agent 自产作品不能自动成为用户正例。

05触发时机

每次回答完成前、话题转换时、长对话出现重要结论时进行轻量判断。不能依赖“关闭窗口”触发，因为 Agent 未必能收到会话结束事件。没有值得保存的内容时不写入，也不向用户额外汇报。

2026-11-02V1.3 · 历史方案

全局无感智脑：每个对话默认有大脑

选择“默认自动使用智脑”，而不是只有输入特定命令才调用。全局 Kimi Code 规则只负责找到智脑；完整规则、个人模型和知识仍只在智脑中维护一份。

01为什么选择默认无感

默认使用智脑

持续个人认知层

每次对话自然读取你的总览和相关知识，逐渐理解你的思路，并在有价值时整理知识。不要求你记得输入命令。

＞符合当前目标
只有命令才使用

按需检索工具

只有明确说“结合文档”才参与，容易错过隐含偏好、上下文和可沉淀内容，不符合长期协作者的目标。

默认自动＋显式控制：选项一作为默认，选项二保留为加强检索或特殊控制的方式，而不是互相排斥。

  • 指出智脑位置
  • 要求遵循默认读取、检索和沉淀协议

03默认无感，但保留自然语言控制

用户表达智脑行为
正常提问或工作读取个人模型总览，轻量检索相关知识
“深入结合一下智脑”扩大检索范围，读取更多相关页面
“这次不用智脑”本次不读取、不写入智脑
“这个不要记”当前内容不沉淀
“记住这个”或“以后照这个做”记录到合适的个人模型或知识页面
“继续上次的工作”在建议架构中读取对应当前工作交接

这些控制语句是已确认的产品思路；是否已写入具体规则文件，应以实际实施记录为准。

04无感不等于无边界

每次自动

个人模型总览、相关索引检索、有复用价值知识的判断。

仍然确认

个人推断、推翻已确认规则、重要合并删除和重大结论变化。

始终不自动

完整聊天保存、敏感信息沉淀、全库读取、GitHub 备份和公开分享。

生效范围：全局入口用于所有 Kimi Code 工作区，但实际文件读取仍需 Agent 按规则执行。新会话是否按预期启动，应在真实新对话中验证。
